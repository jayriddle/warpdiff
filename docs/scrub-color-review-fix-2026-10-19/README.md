## Findings and decisions

The independent adversarial review found a P2 presentation regression and a P3 stale candidate release note. Natural macOS Chrome decoding of tagged BT.709 Main10 HEVC produced opaque (`format: null`) frames. Their raw RGB matched native video, but displayed scrub screenshots differed by up to 12 codes. A separate real ordinary High-profile AVC decoder requested with `prefer-software` emitted I420 and also darkened by 12 codes. The older released baseline's historical correction stayed within two codes for those controls. These were not reasons to apply one curve to every software or opaque frame: the measured High 4:4:4 Predictive AVC/I420 path already matched without it.

The correction keeps native video seeking for opaque/unknown output and ordinary AVC software I420 on macOS. Verified High 4:4:4 Predictive AVC/I420 remains unfiltered for its measured SDR combinations. Verified NV12 BT.709 output retains its scoped compositor correction; wide-gamut NV12 and unverified metadata retain native seeking. Other platforms retain their existing path. Source color labels, decoded pixels and native-video presentation are not rewritten.

Presentation policy now checks every decoder output, including after suspension/recreation. A rejected output or changed filter closes the incoming/pending/cached frames, retires the decoder and clears the canvas before the existing generation-fenced controller releases the encoded-input reservation. Cached frames cannot acquire a new transfer correction. The shared close owner remains idempotent. This also rejects later PQ/HLG output; the earlier first-frame-only HDR gap was present before this feature and is not described as a newly introduced regression.

The consolidated, unpublished 3.19.9 entry in `docs/release-notes-archive.md` now describes this final policy and the retained native A/V playback correction. It no longer claims the tone curve was removed or that untagged inputs use inferred compositor information. The 3.19.8 announcement is unchanged. README, manual, feature description, in-app help and agent guidance agree with the correction.
