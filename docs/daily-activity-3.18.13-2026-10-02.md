## Problem and resulting behavior

Jay reported seeing 18 GoatCounter visits after two video comparison sets plus scrubbing/layout changes. That is operator-reported hosted receipt, not an independently audited event breakdown. GoatCounter's overall total can combine visit and custom-event counts. In 3.18.12, `/` is attempted once per engaged document; keeping a tab open across several days does not renew that figure. `comparison-active` follows provider session deduplication and is not one count per calendar day.

The new stable event `daily-active` estimates consenting browsers that use ready comparisons each UTC day. Ten ready comparisons in one browser/day can produce ten workload counts and one daily activity count. A tab retained from yesterday can count again through deliberate review input, without loading files again. Idle tabs, passive playback, page opening, visibility restoration and consent acceptance alone do not count.

The existing `/`, `comparison-active`, ready-review, feature, scrub and reliability definitions are retained. The GoatCounter overall total will still combine events unless filtered; the new measure is read from its own `daily-active` path. It is not a replacement definition silently applied to historical visits.

## Implementation and decisions

- `js/usage.js` owns daily eligibility, UTC date, atomic cross-tab claim and dispatch. Readiness calls that owner, and trusted pointer/wheel review input calls it in the capture phase. Native control action keys are observed there too, covering controls that stop propagation. The existing recognized hotkey dispatcher calls the same owner after execution, excluding text entry; no key, action ID, pointer position or duration is reported.
- A JSON string containing only the last attempted date is saved to `pref_usageActiveDay`; local testing uses `pref_usageActiveDayTest`. The date is shared across reloads and app releases and retained through withdrawal so No → Yes cannot recount the same day. Nothing identifies or links browsers across days in the adapter's payload.
- A same-origin Web Lock with `ifAvailable` serializes the marker read/write/dispatch. No lock wait or retry queue is created. Unsupported, rejected or busy locks and storage failures skip this optional measure while other eligible reporting continues. A valid future marker suppresses recounting after clock rollback.
- The asynchronous claim rechecks current consent, review/epoch/decision generation, visibility and day. A durable No also blocks a claim before its storage notification is delivered. Replacement, clear, No → Yes, offline transitions, pagehide or a host launch cannot revive an old review's claim. The marker is reserved before dispatch, so blocked, lost or aborted transport is never retried that day.
- Payload: `p=daily-active`, `t=WarpDiff daily active browsers (UTC)`, `e=true`, `ns=true`, empty `r` and a fresh request cache buster. No date, timezone, timestamp, release/media/item cohort, consent record, persistent identifier or media identity is transmitted. Existing credentials/referrer omission and transport cancellation apply.
- UTC gives a consistent reporting boundary across audiences without collecting a timezone. Use a UTC dashboard view for aligned daily buckets. Browser clock errors and server receipt around midnight can distort the boundary; this is a best-effort active-browser estimate, not exact people or completed work. Separate devices/profiles, storage clearing and sharing a browser also affect interpretation. Summing days gives browser-days, not weekly unique users.
- Consent scope remains 4: this clarifies the existing visit/usage-frequency purpose without a new recipient, metadata category, identifier, detailed interaction log or retention policy. This is a bounded implementation assessment, not a claim of legal compliance or general permission for future metrics. Existing scope-4 Yes stays valid; No stays off. Invitation, Details, README, FEATURES, both manuals, scope/event/catalog records and the maintained architecture description were updated together.
- App/service-worker version is 3.18.13. The disclosure/adapter contract is `3.18.13/scope-4`; the HTML integrity hash was refreshed. Missing or mismatched protected revisions retain the harmless fallback, including the new activity method. The initially proposed daily-counting announcement was replaced with the quiet update described below; 3.18.12's important notes remain available to users who missed them.
