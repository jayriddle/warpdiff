# Scrub presence: controlled multichannel reference

## User report and result

Jay reports that scrubbing sounds both quieter and thinner than normal playback, and requested a multitrack test file. This investigation created and tested a **32-second, 48 kHz, 7.1 reference** with eight independent source channels, eight separate mono WAV stems, a multichannel WAV/FLAC, and an H.264/FLAC MP4 with visible section labels.

The reference and the real `de3f…` movie passage confirm **content-dependent level loss in the current Continuous scrub processor**. Input preparation, channel gains, and the steady scrub output fader do not explain that measured loss. Some frequency bands change relative to the overall level as well. Those measurements are consistent with the user's report; they do not fully explain the perceived loss of clarity or establish an accepted fix.

**No playback implementation changed.** The localhost Signalsmith slow-playback prototype and its separate harshness investigation remain unchanged. Drag preview still uses the shared Continuous phase vocoder. The test tools and this baseline are the concrete result of this work; audible presence remains an open quality issue.

### Contents

| Timeline | Signal | What it tests |
| --- | --- | --- |
| 0–8 s | One known tone per channel, sequentially | Channel order, stereo coefficients, unintended leakage |
| 8–16 s | Spoken reference in center alone | Voice level and texture without masking |
| 16–24 s | Identical center speech plus surrounding tones | Dialogue focus and separation from the mix |
| 24–26 s | Four known short noise attacks | Attack smearing and retriggering |

| 27–28 s | Digital silence | Silence preservation and stale output |
| 28–32 s | Center tones at 250, 1,000, 4,000, 8,000 Hz | Frequency-dependent behavior |

Speech is synthesized locally using the installed macOS Samantha voice, at 205 words/minute. The sentence is: “This is the center channel. Clear voices need warmth and detail. Six crisp sounds test speech and breath.” It lasts 5.536792 s inside each eight-second speech section and is placed at the same level and samples in both sections. It is a controlled synthetic voice, not a replacement for real-movie listening acceptance. No movie audio is incorporated into this fixture.

Channel order is FL, FR, FC, LFE, BL, BR, SL, SR. WarpDiff intentionally omits LFE from stereo monitoring: silence during 3–4 s in the stereo output is expected, while the LFE source/stem contains its known signal.

## Tools and reproduction

From the WarpDiff repository, with FFmpeg and the existing Playwright dev dependency available:

```sh
node scripts/create-audio-presence-fixture.mjs --out /path/to/new/reference
node scripts/measure-scrub-presence.mjs /path/to/new/reference/presence-7.1.mp4 /path/to/results 8 16
```

The generator refuses an existing output set. macOS speech synthesis writes to a file without playing sound. Other systems can use `--speech /path/to/licensed-reference.wav`, limited to 7.7 seconds. All calibration signals are deterministic; speech depends on the input file or installed voice version, so the reference manifest identifies the exact generated bytes. Video cards are rendered in an isolated browser, and the MP4 is 768 frames at 24 fps with exactly 32 s of video and audio.

The measurement tool uses the local server on port 8080 (`WARPDIFF_URL` can override it), an isolated physically muted browser, the app's full-rate listening buffer and gain plan, and the actual pinned Continuous processor. It requires a verified surround source. `CHROMIUM_PATH` can select the browser. It saves audio only to the specified local output directory.

Offline rendering uses fixed rates and excludes the first/last 0.2 source seconds from measurements, avoiding startup gain ramps and edge effects. A diagnostic-only message acknowledgement ensures that load/play messages arrive before rendering begins; DSP and render methods are unchanged. It compares the same source-time interval and preserves any real leading audio offset. Spectrum measurements use the existing FFT, 2048-sample Hann windows and 50% overlap, with window-power normalization. The three reported bands are 100–500 Hz, 2–5 kHz, and 5–10 kHz. They are broad diagnostic bands, not an intelligibility score.

The local `validate-reference.mjs` beside the delivered media performs independent FFmpeg/source/stem checks and native-output/real-pointer browser checks. Its hash is retained in the verification record. It has fixed paths for this exact fixture; the two repository tools above are the reusable generators and renderers.

## Verified results

### File, channel and lifecycle integrity

- All eight stems match their corresponding interleaved source samples exactly.
- WAV, FLAC and MP4 decode to identical 32-second, eight-channel sample sequences.
- Each identification segment has the expected 0.12 peak in its named source channel and zero in every other source channel.
- WarpDiff identifies eight original channels and verified 7.1. Its listening copy retains Full Mix L/R plus raw center at 48 kHz.
- Native playback measurements match the existing stereo coefficients: front 0.1200, center 0.084853 to each ear, each side/back contribution 0.042426 to its assigned ear, and LFE zero. Silent opposite-ear observations have positive controls from the corresponding active channel.
- Real five-second forward drags in Full Mix and Center Only remain continuous after startup: 96 active clock observations each, one initial anchor each, and steady output gain 1. Holding/releasing stops the preview. This is one headless-machine run, not a universal gesture-cadence guarantee.
- Original analysis metrics remain byte-equal. Clear returns selected/retiring processor PCM to zero and releases the app context reference. No page errors occurred.

### Average signal level, relative to the same input mix

These are **RMS level differences**, not a subjective loudness score. Rates describe constant scrub tempo, not the J/K normal-playback setting.

| Source / Listen mode | 1× | 0.5× | 0.25× |
| --- | ---: | ---: | ---: |
| Synthetic center speech / Full Mix | −0.0001 dB | −0.73 dB | −2.46 dB |
| Synthetic center speech / Center Only +11 | −0.0001 dB | −0.73 dB | −2.46 dB |
| Movie passage / Full Mix | −0.0002 dB | −2.03 dB | −2.77 dB |
| Movie passage / Center Only +11 | −0.0002 dB | −2.20 dB | −2.93 dB |

The movie measurement uses source timeline 0.70–6.30 s, with its 0.166 s leading audio offset retained. The synthetic speech uses 8.20–15.80 s. An initial narrower movie measurement (1.00–6.00 s) found approximately −2.23/−2.90 dB in Center Only; the small difference comes from the explicitly changed measurement boundaries. Both datasets remain local.

FFmpeg EBU R128 checks also find lower integrated loudness: Center Only movie −2.2 LU at half speed and −2.5 LU at quarter speed; synthetic speech −0.3/−1.8 LU. Gating and frequency weighting mean these values differ from plain RMS. All measured renders are finite and have no above-full-scale samples; true-peak checks over the measured intervals remain below full scale.

### Frequency balance

After accounting for the overall RMS loss, the half-speed movie center retains about **0.52 dB less 100–500 Hz energy**, relative to the total level. The synthetic voice retains about **0.91 dB less 2–5 kHz energy**. The behavior is content dependent; it is not a fixed sample-rate cutoff or one identical missing frequency band. Temporal smearing and phase relationships are not captured completely by these long-term energy comparisons, so audible “thinness” still needs controlled listening.

## Decisions and next correction

1. Keep original inspection data and the shared channel matrix unchanged; both check out in this reference.
2. Treat level preservation and voice texture as separate acceptance criteria for Continuous processing. The 1× reconstruction is a strong positive control; slowing the same stream is where the measured loss appears.
3. Do not apply a blanket +3 dB boost or broad treble boost. Content-dependent loss means a fixed boost can overcorrect other passages, and it cannot restore an altered attack or phase relationship. The earlier harshness case also remains relevant.
4. Use level-matched comparisons and these reference attacks/bands when evaluating a processor correction. Require unchanged center/stereo behavior, no new overload, preserved silence/idle behavior, and acceptance on the real `de3f…` passage plus the earlier preferred E passage. Signalsmith's slow-playback integration is separate; this result does not automatically justify replacing low-speed/reverse Continuous scrubbing with it.

No processor correction has been implemented or declared accepted in this checkpoint.

## Failed checks and their resolution

- The first offline harness produced all-zero output because it began rendering before queued worklet load/play messages arrived. Those results were rejected. A diagnostic acknowledgement and a nonzero-output assertion corrected the harness; the final runs produce meaningful audio and a near-exact 1× positive control.
- The local FFmpeg build lacks its optional `drawtext` filter. The first video-card generation failed explicitly. Cards now use the existing isolated Playwright browser instead.
- The first concatenated-card MP4 ended one 24 fps frame early. Explicit frame-rate conversion and a bounded last-card extension before trimming now give exactly 768 frames and 32 seconds. The initial output remains outside the `verified/` directory and is not the delivered reference.
- The first stem validator used fractional floating-point byte offsets for decimal time boundaries and failed before browser testing. Sample indices are now rounded explicitly; all source/stem and native checks pass.

## Verification and limits

Both new scripts parse successfully; **430 ownership/pure-logic checks pass**. The real-file renderer ran six cases each for the delivered fixture and the movie. The independent validator passed file integrity, lossless equality, eight channel routes, two actual pointer drags, unchanged metrics and cleanup. The MP4 center-speech card was visually inspected. All tool-created browsers exited normally; the user's browser and playback were not controlled.

Production playback code is unchanged, so the full app regression suite was not repeated. Fixed-rate renders isolate DSP from pointer/decoder scheduling; the live gesture probe checks control continuity but does not record every gesture sample for an objective perceptual score. Reverse traversal, CPU/battery cost, physical device response, cross-browser audio quality, and human preference were not established here. Generated audio and private movie captures stay outside Git. The compact measurements, local artifact hashes and reconstruction limits are retained in `scrub-presence-verification-2026-09-22.json`.
