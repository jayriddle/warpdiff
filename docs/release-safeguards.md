# Interim release checks and activation

The small engine-free interim release has two proposed GitHub checks:
**Chromium and ownership** and **WebKit preparation workflow**. They run on
pushes, pull requests targeting `main`, and manual dispatch. There is no
deployment step in this workflow.

The Ubuntu 24.04 job uses Node 24, locked npm dependencies, native FFmpeg and
zsh for fixtures and terminal-command verification, and the Chrome channel for
native media-codec coverage. Bundled Linux Chromium did not provide AAC in the
earlier foundations experiment; installing Chrome avoids that known codec gap.
The job runs the ownership harness and the entire interim Chromium suite.

The macOS 15 job checks copied commands, external preparation, explicit
AAC reload and original-pitch brief previews in Playwright WebKit. It does not
certify installed Safari or native 7.1 FLAC decoding. The two broader
native-surround WebKit failures recorded in
[the original interim verification](external-preparation-2026-10-11/README.md)
remain a separate capability limit, with their assertions retained.

These checks intentionally do not invoke the later audio-measurement or
prepared-contract suites: their runtime changes are outside this release.
Native FFmpeg is a development tool installed on the runner; the app does not
ship, download or invoke an FFmpeg engine.

Actions are pinned to exact commits, the job token has read-only repository
access, and checkout credentials are not persisted. CI rejects accidental
`test.only`, uses one worker and zero retries, limits each browser invocation to 30
minutes, and allows 45 minutes per job. Failure traces, screenshots and HTML
reports are retained for 14 days. Local default Chromium remains available;
`WARPDIFF_BROWSER_CHANNEL=chrome` selects the hosted Linux configuration.

## Approval and activation

1. Review the local interim candidate and approve pushing its feature branch.
   Local passes do not establish that the hosted jobs have passed.
2. Run both hosted checks and verify their exact revision. Resolve failures
   before considering a merge.
3. After approval, require both checks on `main` with up-to-date branches,
   pull-request merges, administrator enforcement, conversation resolution,
   and force pushes/deletion disabled. The [proposed protection payload](
   interim-release-review-2026-10-12/main-protection.proposed.json) is a proposal
   only. Re-read existing remote settings before applying it.
4. Inspect the active protection and verify that failing checks cannot merge,
   using a controlled feature branch if necessary. Do not push an intentional
   failure to `main`.
5. Merge only after Jay's explicit merge/publication approval. The last
   observed Pages configuration deploys from `main` / root; verify that setting
   again before merging. These checks guard an approved merge through branch
   protection; they do not independently intercept a legacy Pages deployment.
6. Verify the served revision/version, absent engine URLs, updated/fresh PWA,
   normal loading, playback, scrubbing and external-preparation reload.

The proposed PR rule requires zero additional GitHub reviewer approvals for
this solo-maintainer repository. Jay's release decision remains required in
the task. No remote setting is changed by adding these files locally.

## Local checks

Install native FFmpeg, run `npm ci`, and install the relevant Playwright browser.
Use `npm run test:fixtures`, `npm run test:ownership`, `npm run test:ci`, and
`npm run test:webkit`. Missing fixtures are also generated by global setup.
CI requires its own port-8080 server so it cannot silently reuse another
checkout; stop an existing preview or use an isolated environment for `CI=1`.

[Playwright media codecs](https://playwright.dev/docs/browsers#when-to-use-google-chrome--microsoft-edge-and-when-not-to),
and [GitHub protected branches](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches).
