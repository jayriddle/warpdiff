# WarpDiff

A/B comparison tool for images, video, and audio. Hosted on GitHub Pages.

- **Repo**: https://github.com/jayriddle/warpdiff
- **Architecture**: `index.html` holds all the HTML/CSS and the bulk of the JS (one `<style>` block top, one `<script>` block bottom), with cohesive subsystems progressively extracted into classic `<script>` files in `js/` (see below). The extracted files are **not ES modules** — they share one global scope with the inline script (top-level `let`/`const`/`function` are visible across all classic scripts in the realm), so an extracted function can read/write inline globals and vice versa, resolved at call time. This is the only viable split given the no-build-step constraint.
- **PWA**: `manifest.json`, `sw.js`, `icon-192.png`, `icon-512.png` — installable, offline-capable.
- **No build step**: vanilla HTML/CSS/JS only, served as static files.

## Key Technical Patterns

### Frame & timecode
- Frame stepping uses midpoint seeking `(frame+0.5)/fps` to avoid IEEE 754 boundary issues.
- Repeated `,` / `.` presses use the burst-local `_frameStepCursor` while a precise seek is unresolved; it expires after 750 ms only once native work has settled. `_queueFrameStepSeek` retains one native seek and the latest target per video, waits for decode plus presentation (150 ms fallback after decode for hidden layers), and fences each issuance. Play commits the queued target before takeover; pause/restart/scope/scrub/clear/visibility retire callbacks and references.
- Timecode display uses `Math.floor(time * fps + 0.01)` epsilon to match frame numbers.
- Passive fps detection (`_setupFpsDetection`) accumulates frame timestamps across normal-playback sessions, normalizes coalesced callbacks with `metadata.presentedFrames`, and snaps to standard rates (23.976 / 24 / 25 / 29.97 / 30 / 48 / 50 / 59.94 / 60). No active probing at load time.

### Layout
- Stack mode `applyZoom()` supports two zoom reference modes toggled by `\` (`_stackZoomMode`):
  - **Fit** (default) — `_perAssetFits[slot] = min(viewW/nw, viewH/nh)`; `fitZoom` = smallest per-asset fit; each asset fills the viewport independently.
  - **Balance** — all assets receive the same rendered screen area: `T = min(perAssetFit² × sourceArea)`, then each slot uses `sqrt(T/sourceArea)`. The minimum fitted area guarantees no asset overflows at default zoom. Entering Balance saves Fit zoom/pan; returning to Fit restores them.
- Equal-area layout for mixed orientations (Grid inline mode): `A = min((availW/Σ√ri)², availH²·min(ri))`.
- Grid layout auto-picks horizontal vs vertical via `pickBestGridLayout(n)` — computes rendered area for each option given viewport dimensions and asset aspect ratios; re-evaluated on resize.
- Four-input visual comparisons use the `quad-grid` 2×2 Inline layout with equal rendered area across all four cells. Hiding a slot falls back to the existing three-/two-/one-item layouts; four audio inputs stay vertically stacked.
- Three-phase layout: measure → compute geometry → DOM write. Debounced functions use the pattern `functionNameDebounced` wrapping `functionName`.

### Playback scope (Sync / Solo)
- `_playbackScope` and `_soloPlaybackSlot` are written only by `_commitPlaybackScope`; all transport consumers resolve participants through `getTransportSlots`, `getTransportPlayableMedia`, or `getTransportVideos`.
- `Shift+S` toggles Sync/Solo for comparisons with 2+ videos. Solo follows the selected video for play/pause, restart, stepping, speed, scrub, loop wrap, progress, and Opus replacement audio. Selecting another video calls `_setSoloPlaybackSlot`, transferring the timeline and play state; returning to Sync aligns all videos to the solo clock.
- Unequal-length handoffs retain absolute time in `_soloHeldTimelineTime`: a shorter target holds paused at its final frame, Full Sync restores the retained longer position, and a range-limited Sync anchor outside its bounds restarts at the shared in-point. Custom loop markers remain global; `_customLoopBoundsForMedia` clamps the effective Solo out-point and treats an in-point beyond the target duration as unavailable. `_getEffectiveDuration(video)` must resolve the supplied element's slot with `getMediaSlot`, never infer it from `currentAudioSource`.
- The multi-clip Sync/Full loop-range control is hidden in Solo. Custom in/out points still apply to the solo participant.

### Loop in/out enforcement (RVFC chain)
Sub-region looping is enforced *frame-accurately* via `requestVideoFrameCallback`, not rAF.

- `_startLoopRvfc(video)` registers an `onFrame` callback that checks `metadata.mediaTime` against `_loopInPoint` / `_loopOutPoint` and seeks back when out of range. The callback always re-registers itself at the end (single chain, no duplicate callbacks).
- **Scheduled exact-time wrap**: `mediaTime` is quantized to the frame grid, so waiting for a frame *past* the out-point lets up to a full frame of audio (~42 ms at 24 fps, plus seek latency) play beyond the boundary — audibly. When the **last in-region frame** presents (`t >= out − frameDur·1.25`, `frameDur` from `videoFrameRates`), `onFrame` schedules `_loopWrapToInPoint()` via `setTimeout` for the exact out-point time (playback-rate aware). The timer re-validates before firing (loop cleared / paused / user seeked back) and is cancelled by `clearLoopMarkers`; the immediate `t >= out` check remains as the safety net.
- **Critical**: never register both `requestVideoFrameCallback` *and* an `'ended'`/`'playing'` event listener as fallbacks at the same site — they create parallel chains on stall and dead chains on non-stall. RVFC's contract is "fire when next frame is presented," which covers both the post-seek and post-stall cases on its own.
- The `'play'` event handler in `setupVideoHandlers` must start the RVFC chain **before** the `_bulkSyncActive` early-return; `playAllMedia` flips that flag for 50 ms and the chain would otherwise never start.
- `playAllMedia` and `restartAllVideos` share `_preparePlaybackStart`: cancel stale play intent, validate Solo bounds, suspend retained scrub decoders outside a drag, apply `_applyNativeLoopPolicy`, and resolve/pause media by playback scope before playing. Scrubbing temporarily disables native loops; both entry points must restore the policy. Native loop is enabled only for current transport participants when no managed loop region is active. Otherwise native loop fights the RVFC seek-back. Suspend retains cached frames and demuxed bytes for the next drag.
- `setLoopPoint` clamps `media.currentTime` to `_getEffectiveDuration(media)` before storing, so loop markers stay inside the media timeline. Decoded audio duration cannot shorten that timeline.
- A `'ended'` handler wraps to in-point when custom loops are active — the RVFC out-point check fires on `mediaTime >= _loopOutPoint`, but the last frame's `mediaTime` is typically one frame *short* of duration, so an out-point at the end never trips the check and the video ends instead. The handler restarts playback at in-point.

### Audio decode pipeline
1. **`decodeAudioData()`** — native browser decode. Race against a timeout: 1 s if WebCodecs is available (fast fallback), 30 s otherwise.
2. **WebCodecs `AudioDecoder`** — for codecs `decodeAudioData` doesn't handle (notably Opus in Safari, and Opus in Chrome where decode is "successful" but timing is wrong). Demuxer (`_demuxMP4Audio` / `_demuxWebMAudio`) extracts packets manually.
3. **External preparation** — unsupported video soundtracks receive a copied command and reload instructions.

The fallback routing is **`_onAllDecodeFailed(slot, audioConfirmed)`**:
- If `audioConfirmed=true` (WebCodecs already extracted packets but couldn't decode them — e.g. DTS-HD MA muxed with `mp4a` fourcc, malformed AAC, HE-AAC marked as LC), always offer external preparation.
- If `audioConfirmed=false` and the byte scanner didn't find a known unsupported-codec signature (`ac-3` / `ec-3` / `dtsc` / `dtse` / `dtsh` / `dtsl` / `mlpa`) inside MP4 box atoms, *and* the file is a video, treat as "no audio track" and skip external preparation. (Without this distinction, files with confirmed-but-undecodable audio get silently dropped.)
- Otherwise call `_registerFfmpegCommand` which registers a safe external command and opens the preparation panel.

### MP4 audio demuxer (`_demuxMP4Audio`)
- Walks `moov → trak → mdia → mdhd / hdlr / minf / stbl → stsd / stsz / stco / co64 / stsc / stts` and `trak → edts → elst`.
- `_isMP4AudioContainer` is the shared recognition owner for video/lazy decode, audio-only decode and WebCodecs fallback. It follows top-level box boundaries through leading padding/unknown boxes, with a 64-header budget. Identified malformed/padding candidates and exhausted plausible prefixes still require metadata verification; neither may silently enable native analysis. Recognition does not certify container validity. Movie headers are unique: a second `mvhd` rejects both metadata and packet extraction before publishing timing. Duplicate-header tests must retain valid absolute sample offsets and a passing single-clock control.
- **Per-track scoping is mandatory** for the complete MP4 audio track: ID, handler, codec/configuration, sample-rate/channel metadata, edit lists, sizes, offsets, chunk map and timing. State is created at `trak` entry, independent of child-box ordering. `_demuxMP4Audio(data, metadataOnly, selectedTrackId)` selects the sole audio track automatically, or a uniquely identified track only when the caller explicitly supplies its ID; it never concatenates tracks. The app has no portable native-track identity, so ambiguous/unreadable recognized MP4 inputs retain native playback and withhold decoded tools through `_setAudioTrackIssue`. Both video/lazy and audio-only owners apply that policy before native decoding; host audio-only loads fail when required analysis is unavailable. Source metadata still lists all tracks.
- Audio extraction validates compact tables, complete sample/timing coverage and `mdat` byte ranges before packet copies. Limits: 64 tracks, 100,000 boxes, one million packets, 256 MiB copied packet bytes and 64 KiB codec configuration. These do not bound initial file reads, decoded PCM or whole-browser memory. Metadata mode never copies packets; malformed extraction returns `null`. Behavioral and allocation-order checks live in `tests/mp4-audio-malformed.mjs`, with actual-browser/host checks in `tests/mp4-audio.spec.ts`.
- Returned `extracted` shape: `{ chunks: [{timestamp, data}], sampleRate, channels, codec, description, preSkip, maxSamples, timelineStart, trackId }`. `preSkip` and `maxSamples` are applied post-decode to trim encoder priming and edit-list-truncated tails. MP4 `dOps` is converted to a version-1 `OpusHead` description (little-endian numeric fields, mapping table intact) before WebCodecs; raw dOps can silently decode multistream surround as stereo. The decoder-only OpusHead copy clears pre-skip because the post-decode owner applies priming/edit-list trimming once (also for WebM). Tests compare decoded center samples against FFmpeg to catch channel reorder and double priming trim. Both audio-only and lazy W-panel decode paths must read the same WAVE/FLAC layout metadata; independent completion order must not disable center controls.
- Metadata-only MP4/WebM parsing returns `audioTracks` without packet copies. MP4 also exposes `timelineVerified`; reports require a real movie clock even when legacy decoding retains fallback timing. `_setVideoAudioFormat` in `js/audio-decode.js` owns the per-video source-format readout with the same decode-generation fence. Codec declarations, FLAC STREAMINFO, AAC AudioSpecificConfig, and Opus/WebM headers supply display metadata; decoded playback/scrub buffers must never supply the source channel count or rate. Multiple tracks are listed without inferring browser selection. Clearing a comparison drops the metadata with `mediaData`; reloading a prepared file replaces it through the new decode.

### External audio preparation
- The browser app ships no FFmpeg wrapper, engine or sources and performs no conversion internally. Explicit local preparation is coordinated through the separate connection adapter. The optional repository-only Node tool invokes user-installed FFmpeg/ffprobe externally and is not staged or downloaded by the app. Native decoding and WebCodecs remain available.
- `_registerFfmpegCommand` opens the external-preparation panel; `_setFfmpegPanelOpen` owns opening/closing and focus restoration. Tab/Shift+Tab wrap within the modal preparation panel; rerenders preserve focus on Copy, download or reload controls and reveal those controls when content grows. Reopening resets panel scroll to its heading. Commands are listed in `assetOrder`.
- `_ffmpegLoadEpoch` and command identity fence asynchronous clipboard results. Clear/reload closes the panel and retires its entries. No converter queue, progress, worker or automatic file replacement remains.
- POSIX commands quote literal basenames, prefix paths with `./`, and refuse C0/C1/DEL terminal controls. Extensionless names stay intact and gain `_aac.mp4`.
- The existing MP4/MOV command applies edit lists, copies the first video stream, converts the first audio stream to stereo AAC at 48 kHz / 192 kbps, pads a short soundtrack with `-af apad` before `-shortest` so the complete picture is retained, and moves metadata forward with `+faststart`. It is a compatibility copy, not original multichannel analysis. Commands are offered for MP4/MOV-style extensions (`.mp4`, `.mov`, `.m4v`) and extensionless names; other extensions display a preparation notice with Copy disabled. This is a filename-based guard, not validation of the container bytes. Other containers require a different external command, and copied video codecs must be supported by the browser.
- Users install FFmpeg independently and load the prepared output with their other comparison files through the existing Load/drop workflow. Managed hosts prepare and reload through their own channel; legacy `capabilities.ffmpegTranscode` cannot enable browser conversion and is always false locally.
- Service-worker activation retires the old app caches and the exact legacy `warpdiff-ffmpeg` cache. Historical Git bundles and prior distributions require separate remediation.

### Opus / Chrome Web Audio sync replacement
Chrome's `<video>` element produces incorrect A/V timing for Opus audio tracks. For affected slots we mute `<video>` audio and play the decoded `AudioBuffer` via Web Audio.

- `_opusSyncSlots[slot]` flags the slot as needing Web Audio replacement. `_opusSyncActive` is the global toggle.
- `_getEffectiveDuration()` uses the supplied native media duration. Audio PCM never changes picture duration or triggers an early picture wrap. Opus eligibility comes from a unique parsed track and is confirmed by the WebCodecs codec at publication; metadata text never selects replacement.
- `_startOpusSyncAudio(slot, fromTime)`: creates an `AudioBufferSourceNode` at the slot's video's `playbackRate`, fades in over `_OPUS_FADE` (15 ms). Starts at `max(now, _opusSyncFadeUntil[slot])` — `_stopOpusSyncAudio` stamps `_opusSyncFadeUntil` whenever it fades an *audible* source, so any stop→start sequence (internal replacement or external pause→play) waits out the fade rather than crossfading uncorrelated audio with it. The buffer offset is advanced by `(startTime − now)·rate` so audio aligns with the still-advancing video at the actual start moment (starting at `fromTime`'s sample would bake a permanent lag into the drift anchors). Records the **scheduled start time** in `_opusSyncStartCtx` (possibly future), start video time, and the rate per slot.
- **Deferred-start window**: for up to `_OPUS_FADE` after replacing an audible source, the new source exists but hasn't started and all its gain automation is in the future (`gain.gain.value` still reads the GainNode default 1.0). Every consumer of the per-slot state must handle `_opusSyncStartCtx[slot] > ctx.currentTime`: `_syncOpusAudioToVideo` skips drift checks (`elapsed < 0`), `_updateOpusSyncRate` skips re-anchoring, `_updateOpusSyncGains` re-schedules the pending fade-in instead of writing `.value`, and `_stopOpusSyncAudio` cancels the scheduled start outright instead of running a value-anchored fade (which would anchor at 1.0 and let the source start un-faded). Silent cancels and natural ends leave `_opusSyncFadeUntil` untouched — it tracks the last *audible* fade.
- `_syncOpusAudioToVideo()`: drift-corrects each slot. `expectedVideoTime = startVideo + (ctx.currentTime - startCtx) * rate`. Restarts the source if drift > 150 ms OR if `video.playbackRate` changed (the AudioBufferSourceNode's rate can't change mid-stream without an audible glitch).
- J/K speed handlers call `_updateOpusSyncRate(rate)` which re-anchors the timeline (`startVideo` updated to current expected position, `startCtx` to current `ctx.currentTime`) before assigning the new `source.playbackRate.value`.

### Scrub audio preview
- Safari native video drag seeks route through `_queueNativeScrubSeek` in `js/transport.js`: one in-flight seek and latest target per visible video, with a paint frame after `seeked`. Normal drag completion and media clear cancel this owner before final seeks/cleanup; hiding the document retires the gesture and its deferred resume. `_onPageRestore` refreshes geometry and video surfaces; `_forceVideoRepaint` preserves rotation and defers to any newer layout transform. Native mono/stereo output avoids Safari's measured Web Audio post-backward-seek picture stall; surround output still uses the monitoring graph and can retain the delay.
- Exactly one preview-audio owner: `playScrubSnippet` resolves `currentAudioSource` (or the active Stack slot fallback). Grid may decode/paint three videos, but never creates scrub audio for the two unselected slots.
- `_feedScrubAudioMotion` owns gesture activity; `_feedScrubAudio` owns the audible target. The steady 50 ms clock renews grains even at an unchanged frame PTS while the pointer is active, and stops after 130 ms idle. Late presentation callbacks cannot extend activity; repeated clamped edge targets are idle. Multi-video Grid uses the shared pointer timeline; single-video scrubbing retains the displayed-frame anchor.
- Click, warm-up and fallback grains play at original pitch with a constant 90 ms **output** duration, independent of the selected normal playback rate. Adjacent grains overlap and use the existing 10 ms held-gain ramps plus bounded ±8 ms phase alignment. Near the end of the source, the remaining samples shorten the grain.
- WebCodecs scrub targets are also globally rAF-coalesced: raw pointer events record the newest time, then one display-frame owner fans that target to all visible sessions. The first direct/click target remains immediate.
- Storage: full-quality original `AudioBuffer` for Chrome Opus sync replacement. Other videos keep a separate listening copy at the AudioContext rate, capped at 64 MiB per slot: mono/stereo normally, or Full Mix L/R plus raw center for verified surround. All three planes count toward both preview and selected-stream budgets. Oversized copies use filtered 22050/16000/11025/8000 Hz short-preview fallback; if none fits, preview is unavailable with a notice. `_scrubPreviewPlan` and serialized `_prepareVideoScrubBuffer` in `js/audio-decode.js` own preparation; generation checks fence clear/reload. `_populateNoVideoSlotData` reuses original `waveformData` / `spectrogramData`, never recomputes from listening PCM. Audio-only source buffers stay intact for analysis. The selected Continuous processor has its own 64 MiB cap and automatically falls back to snippets; no mode preference or selector.

### Audio & video metrics
- EBU R128 / ITU-R BS.1770 in `computeAudioMetrics(audioBuffer, channelLayout)` (`js/audio-viz.js`). K-weighting is the published pre-filter plus RLB high-pass: 48 kHz uses the Recommendation's coefficients, and other rates use the same bilinear design. Verified 5.1/7.1 layouts are passed through both analysis paths; surrounds are weighted by 1.41 and LFE is omitted. Mono and stereo weight each channel at 1. An unverified multichannel layout sums every channel equally, because the positions are unknown, and the info bar marks that LUFS and LRA reading as approximate. 400 ms gated blocks → integrated LUFS; 3 s short-term blocks → LRA. True peak is the BS.1770 Annex 2 49-tap Hann-windowed sinc (4× below 96 kHz, 2× below 192 kHz, sample peak from 192 kHz).
- Spectrograms at 120 s or longer use one 2048-point FFT with an adaptive hop capped at 8,192 frames per channel. Hann coherent gain is compensated so Ref mode reports a bin-centred full-scale sine at 0 dBFS.
- Info bar shows `LUFS · LRA · TP`. CSS `:empty { display: none }` auto-hides absent metrics.
- LUFS envelope (E key cycles modes): Waveform / Waveform+LUFS / LUFS only. Short-term LUFS drawn as stepped chart, reference lines at −14 (streaming) / −16 (podcast) / −23 (broadcast).

## Coding Conventions

- No build step, no dependencies — vanilla HTML/CSS/JS only.
- CSS is in a single `<style>` block at the top of `index.html`; most JS is in the single `<script>` block at the bottom. Cohesive subsystems are extracted into `js/*.js` classic scripts (see Files) — prefer extending an existing module when the code belongs to its subsystem; otherwise edit `index.html`.
- Use `_prefixed` names for module-level private state (e.g., `_audioSlotVizData`, `_opusSyncSlots`). (Note: `_frameStepping` does not exist; the synchronization-suppression owner is `_bulkSyncActive`.)
- Debounced layout functions use the pattern `functionNameDebounced` wrapping `functionName`.
- **Single-owner discipline**: each piece of stateful behavior should have ONE owner (one function that writes it; everyone else routes through it). The ownership harness (`tests/ownership.test.mjs`) enforces this for the audited cases — when adding/refactoring an owner, update the corresponding guard.
- Help and What's New body typography is owned by `.quick-start-body` in `index.html`. Paragraphs, lists and tables inherit its 13px body size; headings and keyboard badges keep their separate roles. Avoid section-specific or inline body-size overrides. Getting Started keeps appearance/privacy guidance brief and points to the full disclosure in Appearance and privacy.
- **`APP_VERSION` in `index.html` and `CACHE_NAME` in `sw.js` must be kept in sync on every version bump** (now guarded by the ownership harness). The service worker uses `CACHE_NAME` to invalidate the cache for installed PWA users.
- Keep `#changelogPopup` to one meaningful-release summary with two or three short, user-facing bullets. `_CHANGELOG_VERSION` owns the last release worth announcing; `_shouldShowChangelog` compares it with `lastSeenVersion`. Quiet maintenance releases keep the prior summary and do not repeat it for users who have already seen that release. Users upgrading from an older release can still see important changes they missed. Consolidate unpublished iterations; omit minor fixes, implementation steps and development details. Preserve detailed history in `docs/release-notes-archive.md` and project verification records instead of accumulating it in the popup.

## Testing

`npm run test:preparation` runs real external-tool fixtures, picture/timing/cleanup checks, and SDR test-fixture packet preservation sequentially. It needs existing fixtures and system FFmpeg/ffprobe; CI runs it in the protected ownership job after fixture generation. Package unit/fault checks also run through ownership, and prepared-media.spec.ts runs in Chrome/WebKit.

Two layers:
- **Behavioral (Playwright)**: `npm test` / `npx playwright test`. Real headless Chromium; state inspected via `__testAPI`.
- **Structural + pure-logic (`npm run test:ownership`)**: `node tests/ownership.test.mjs`, dependency-free, no browser. Reads concatenated sources (`index.html` + `js/*.js`) and asserts: single-owner guards (RVFC loop chain, video handler binding, decode generations, opus-sync restart, decode pipeline, transport cluster), build/version hygiene (`APP_VERSION` == `CACHE_NAME`; every `<script src=js/*>` is in `sw.js` ASSETS), inline-`<script>` syntax, and pure-function unit tests (incl. the MP4 demuxer against a real fixture). Guards use `countOf`/brace-balancing `extractFn`; each freezes a specific competing-owner bug and is verified to fail when its fix is reverted. Run both before pushing.

- Playwright. `npm test` or `npx playwright test` runs the suite from project root.
